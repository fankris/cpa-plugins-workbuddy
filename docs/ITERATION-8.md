# 第八轮：插件内账单业务链路修复

版本 `v8.0.15-2.0.0-rebuild.8`，2026-10-06。

## 定位到的问题

1. 新 UI 只请求 `/accounts`，该入口却调用不抓取积分的旧轻量分支，假定前端仍会逐账号懒加载。冷缓存时套餐与积分可能一直为空。
2. 账单解析只读 `Response.Data.Accounts`，扁平 `Accounts` 形状没有被正确读取。过去部分测试仅检查返回对象存在，未核对余额。
3. 套餐只取第一页，未使用 TotalCount 完成分页。
4. 非 2xx 响应若恰有 code=0 可能被按成功解析；缺少账单数据也可能退化为零余额。
5. 缓存刷新失败时可能给旧积分加上新抓取时间，而且后续缓存命中不再报告错误。
6. 双轨菜单声明已存在，但旧管理路径缺少 HTML/JS/CSS 的实际处理，菜单被识别不代表能打开。

## 已实施

- **插件内部执行**：初次账号读取即通过 CPA auth store 取得凭据，插件调用上游账单逻辑、解析套餐、汇总积分并返回页面。不依赖独立 Manager 服务。
- 按账号限制并发为 4，复用已有 45 秒缓存和 singleflight。初次读取不触发签到、奖励领取、生命周期变更或账号备注写回；手动操作保持独立。
- 兼容嵌套与扁平账单格式，完整汇总分页套餐；最多 100 页，总抓取时间限定 30 秒。分页异常或数量变化明确失败，不把部分余额冒充完整余额。
- HTTP 鉴权失败、缺失账单结构返回错误，不把未知伪装为零积分。
- 仅新取到的积分更新 fetched_at。失败时保留旧快照及其原时间，缓存命中继续报告刷新错误。
- 保留双轨菜单；补齐旧路径的 panel、panel.js、panel.css、panel-i18n.js 声明与处理，仍交由 CPA 管理鉴权保护。现代 resources 保持原样。
- UI 没有伪造余额或客户端积分计算；原有 PC/手机布局继续保留。

真实积分属于 WorkBuddy 上游，插件负责读取和合法业务处理，不能在本地凭空生成积分。CPA 继续负责账号、传输和原生管理能力。

## 验证

- Go race：539 PASS / 1 可选 SKIP；Go vet、官方 SDK 固定版本源码契约 PASS。
- 强化管理入口测试：冷缓存读出模拟上游的 88 积分和 Free 套餐；第二次使用缓存；没有账号凭据写入。
- 扁平 native quota 测试明确校验 75 积分，不再只检查响应对象。
- 新增缺失结构、401/403、跨页聚合检查；缓存失败测试校验旧抓取时间和错误不会消失。
- **实际编译 .so 的 C ABI 模拟宿主检查：10 组 PASS**。覆盖双轨菜单及两套资源路径、冷启动账单汇总 75 积分、第二次缓存命中及不写凭据。模拟宿主通过 CPA HTTP 回调提供数据，不是让浏览器直接收到预造的 accounts 响应。
- 前端 TypeScript/build PASS；Node 61 PASS；浏览器 62 场景 + 普通 HTTP PASS。
- HTML 新采集 10 张当前 UI 截图。截图的数据来自浏览器夹具；截图本身不是后端账单验证证据，两类证据明确分开。

## 边界

未接入真实 CPA/CPAMC 实例或真实账号，未更改生产或云端数据。签到、奖励领取、试用及旅行没有新增真实业务验收。本轮不能宣称所有功能已在真实账号恢复，更不能保证所有历史宿主均兼容。旧管理页面仍依赖宿主正确处理鉴权和菜单去重；双轨注册不改变插件 ABI/schema 6 的加载要求。
