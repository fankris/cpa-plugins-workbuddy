# 第十一轮：改工作区结构，不再用顶部空白躲避悬浮控件

版本 `v8.0.15-2.0.0-rebuild.11`，2026-10-06。

用户明确指出问题是 CPAMC 右上角的宿主控件，而不是账号详情弹窗。上一版手机整块留白虽然避免遮挡，但没有形成合理工作区。本轮改结构。

## 新结构

- CPAMC 桌面：短分区导航与宿主控件共用顶部一行。导航左侧、宿主控件右侧；业务区全宽，控件变宽不再改变业务区的位置和宽度。
- CPAMC 手机竖屏：顶部可用区域显示当前分区；账号、模型、任务、结果放到底部导航。底部导航是正常文档流中的固定高度布局行，不是另一层悬浮浮框。
- 手机横屏 / 宽视口：使用顶部联合导航，避免底部导航额外挤掉列表高度。
- 不再为已识别的 CPAMC 悬浮布局添加整页顶部 padding。手机保留 8px 基础边距；顶部是真实工作区标题行，不是空占位。
- 已识别的宿主控件隐藏后，释放横向避让宽度，但导航仍留在既定区域，不因控件显示/隐藏来回换位置。
- 模拟数据标记移到这类布局的页底；生产页面本来就没有演示标记。
- CPAMP 外置标题栏、独立页面保留其原有结构；不隐藏、不移动、不改写宿主控件。
- 非典型整行覆盖层和无法读取的跨域宿主仍需保守处理。跨域不可测量时仍保留旧的安全回退，不能冒称所有安装方式都已精准适配。

## 测量与验证

同样的 390×844、同样的模拟数据：首个账号从第十轮约 y=304px 提前到本轮约 y=230px。四个完整账号仍可见，分页与底部分区导航分开，没有覆盖账号行。改善的是顶部内容组织与操作位置，不声称凭空增加整个视口容量。

新增 4 个结构场景：320×568、390×844、844×390 各检查四个工作区的导航位置、标题可见性与初始账号列表；桌面额外验证宿主控件变宽时业务区 x/y/width 不变。宿主模拟页面补上真实移动浏览器所需的 viewport meta，触屏测试不再借桌面默认视口掩盖问题。

完整回归：浏览器 87 场景 + 普通 HTTP PASS；Node 61 PASS；TypeScript/build PASS；Go race 539 PASS / 1 可选 SKIP；Go vet 与 SDK 契约 PASS；编译后二进制 C ABI 模拟宿主 10 组 PASS。
