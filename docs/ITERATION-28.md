# rebuild28 — 状态可信度与恢复能力

版本：v8.0.15-2.0.0-rebuild.28。CPA 8.0.15 / ABI 1 / schema 6。生产未修改。

## 重要行为变更

**所有已停用账号均不再被插件自动启用，包括此前由插件因积分耗尽而停用的账号。** 积分恢复后，请通过账号详情里的 CPA 原生“启用账号”明确恢复。

原因：当前使用的原生接口不提供可靠的停用来源与人工变更版本/CAS，不能仅凭余额、备注或插件内存标记判断用户意图。没有建立第二套账号/配置存储。健康账号维护也不再通过整份凭据写回同步备注，避免顺带写入 disabled:false。自动生命周期仍可处理新鲜、确认的积分耗尽。

## 修复清单

- A01：停用账号协调直接保持原状态；自动重新启用入口为无写入保护。设置页四语言说明同步更新。
- A02：生命周期决策检查积分自身的成功采集时间与积分错误，而不是整个缓存条目的更新时间。读取失败可保留旧值用于展示，但不得用来修改账号状态。
- A03：结果函数不再默认成功。逐账号保留 uncertain/code；聚合保留运行中、取消和未确认。维护接口使用独立返回契约；令牌刷新不再由前端制造成功标记。仅已知 CPA 原生操作的 204 是允许的空确认；插件写操作空响应为未确认。
- A04：状态 GET 支持抖动退避，连续六次失败后暂停；手动刷新与网络恢复可续查同一个 run_id。401/403/404/410 停止重试。账户/运行 ID 验证，卸载后丢弃迟到响应。不会重发接受/领取等写操作。
- A06：缓存发布收拢至 CAS 更新入口；请求开始前分配代际，分别合并积分/签到/套餐字段，旧请求不覆盖较新的字段。失效设置代际屏障；签到更新不清除积分错误。积分在真实读取完成时取得时间戳，覆盖自动签到和原生额度路径。
- A07：credits 与 credits_expiry 使用共同的新鲜度判断，错误/过期/缺时间/未来时间不能作为可信积分。只失败的签到字段不污染独立成功的积分。原生 ConfigFields 补齐 credits_expiry 选项。
- A08：billing POST 只读接口采用明确重试白名单；签到和试用不自动重放。写入 5xx、传输/解析异常保留未确认；业务拒绝与已领取保持明确语义。签到软失败不再仅凭“今日”字样变成已签到，也不在拒绝后补造已签到缓存。
- A09（部分闭环）：修复过时官方宿主测试，实际加载本次发布二进制，验证原生鉴权、菜单/资源、空账号、配置读写/运行态与四语言 iframe 重挂载。真实账号业务仍未验收。
