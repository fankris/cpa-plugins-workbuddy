# 第二轮：按 CPAMC 内置业务页迭代

版本：`v8.0.15-2.0.0-rebuild.2`。本轮目标不是继续装饰独立面板，而是减少重复导航并修复可复现的操作故障。

## 已复现并修复的故障

旧版在 `perform()` 的 try/finally **之前**执行 `crypto.randomUUID()`，同时已经把 busy 设置为 true。普通 HTTP 页面可能没有 randomUUID：抛错后业务请求完全不会发送，busy 也无法复位，造成整组变更按钮一直失效。

修复：操作记录的关联 ID 改用不依赖 Web Crypto 的本地生成器（不是安全令牌）；同步锁避免重复提交；变更流程用 finally 释放状态。没有降级管理鉴权，也没有自动重发上游变更。

证据：`validation/iteration-2/before-fix.json` 记录旧版的异常与锁死。新版既测试了缺少 randomUUID 的环境，也在实际普通 HTTP 域名下确认 `isSecureContext=false`、`crypto.randomUUID=undefined`，操作请求和状态恢复仍通过。这是已证实的一类故障，不代表已经确认用户所用环境的所有故障都出自同一原因。

其他修复：
- 登录态由账号接口响应确认；401 后可输入替代密钥并立即验证、恢复操作，不只是把界面标成已连接。
- 变更响应不是 JSON 时标记“结果未确认”，不误报成功，不自动重试。
- 模型发现页面的刷新确实刷新当前账号发现，不再误刷另一个目录；修改模型开关后重新读取发现状态。
- 任务账号切换同步查询最近运行；运行面板显示状态、接受数量、失败数量与时间，原始 JSON 收入详情。
- native credentials 的 name 优先用实际文件名，再退回 auth_id。

## 功能区域重新组织

1. **页面级：**删除 WorkBuddy / CPA 原生插件标题栏、⌘K、浮动 dock、装饰性 WORKSPACE 编号和重复页脚。只保留一组业务标签与当前业务区的操作工具栏，预留 CPAMC 自己浮动工具栏的区域。
2. **账号区：**压缩汇总为一条统计区域；账号启停、进入该账号任务、查看详情直接位于表格行内。不让用户为了常用操作层层找弹窗。活动账号选择只在 credits 调度模式下显示，不给 host 模式放无效选择入口。
3. **模型区：**区分配置目录与按账号发现；刷新跟随当前视图，失败提示在页面中展示。
4. **任务区：**从账号进入时携带账号上下文；增加全部/可领取/未接取/已接受筛选；操作记录用可读摘要，非默认裸 JSON。
5. **结果反馈：**最近操作结果持续显示在页面内，可以直接查看详情；不再仅靠几秒即消失的 toast。

独立预览保留页尾语言/主题工具；在 CPAMC 嵌入时仍由宿主控制。导入草稿继续仅在内存保留。合法任务保留，不支持虚假活跃或伪造完成。

## 本轮实测

- Go race：506 个命名测试/子测试通过；1 个可选 wire-shape 导出辅助项跳过；Go vet 通过。
- Node：31/31。
- 原浏览器回归：12 项。
- 新故障/交互浏览器回归：11 项（缺失 Web Crypto、行内启停、断网/非 JSON 恢复、账号任务入口、任务过滤、正确刷新、导入回读、协作取消、401 恢复、布局）。
- 实际普通 HTTP 场景：通过。
- 当前二进制实际官方 CPA 8.0.15 / CPAMC 1.25.3 空账号集成：12 项通过。

测试源码分别为 `tests/iteration-2-browser.mjs`、`tests/plain-http-browser.mjs`、`tests/rebuild-browser.mjs`、`tests/real-host-integration.mjs`。新证据在 `validation/iteration-2/`，原回归证据也已刷新。

**不能宣称真实账号业务全部恢复：**没有接入用户报告故障的实际实例，没有用真实凭据跑推理、刷新、签到、奖励、试用与旅行。导入与有账号操作测试使用明确标识的本地夹具；官方宿主测试为空账号。前一轮的空宿主 PASS 不足以证明真实业务可用，本轮不延续这一过度推断。

生产、密钥、账号与回滚卷未改动。二进制仅 Linux amd64 / glibc ≥ 2.34，使用前仍需在隔离实例验证实际账号。
