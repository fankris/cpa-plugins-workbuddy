# 21：模型优先，而不是诊断优先

版本 v8.0.15-2.0.0-rebuild.21 · 2026-10-07。

## 本轮纠正的方向

用户明确否定了常驻“部分渠道未取得完整目录”提示和此前多轮模型页效果。本轮不继续向首屏增加诊断卡片，而是重新核查 Manager 固定提交 `508f803425ce74edc5b7dd6a082ceb415e1c7b62` 的 `web/app/(main)/models/page.tsx`：它把可搜索模型表放在主流程，失败日志默认折叠。借鉴信息层级，不复制独立管理后台、统计卡与布局壳。

## 用户可见变化

- 移除常驻通用黄色警告和三块渠道状态卡；不自动展开来源/排错信息。
- “全部 / 动态获取 / 自定义”变成可操作的紧凑筛选标签，配搜索、渠道筛选与排序。
- 同ID仍一行，名称下面标来源；渠道使用短标签，实线为目录返回，虚线为仅配置。完整渠道名在来源弹窗、模型详情和悬浮说明中可见。
- 模型表显示具体上下文、输出、倍率与推理档位，不再反复填“按来源不同”。
- **参数取值没有伪造共识**：取筛选后第一个可见variant（与行名称一致）；如果各来源关键参数有差异，在参数栏标注渠道＋动态/配置和星号，详情保留各来源原值。切换渠道后数值随可见来源变化。按倍率排序仍把冲突/未知共识置后，不把未知当免费。
- “来源账号”是用户主动打开的对话框，不挤压或推走模型表。每渠道一个账号，手动选择只改变观察来源，不改实际CPA选中账号和路由。
- 来源对话框里的路径、HTTP/业务code、恢复建议再置于“技术详情”折叠项。未支持渠道只有中性说明，不提供无效的动态来源选择操作，自定义模型仍保留。
- 只有实际 failed/partial 目录请求或凭据读取错误才显示一行具体提示，如“国内：账号认证未通过”。不会自动弹窗，不阻断其他渠道和自定义模型。
- 账号不可用/手动来源失效通过来源按钮的待处理计数和弹窗状态说明；无模型时提供选择来源或清除筛选入口。
- 旧 hubSourcesOpen 状态退休，不因前一轮自动展开记忆而再次占据首屏；用户需要时再打开弹窗。

## 后端语义修复

原聚合状态把 unsupported 也算作partial。预览恰好含未验证的CodeBuddy国际渠道，因此每次都出现全页“部分获取”警告。现在 unsupported 和 no_account 不算获取失败，状态仍原样列于 sources；真正失败、部分成功及不可用来源没有被改成成功。前端也不再仅凭顶层partial决定弹出通用警告。

保留20轮修复：Manager realm凭据映射、已知过期来源排除、企业候选路径和字符串业务code、宿主HTTP回调作用域与令牌/缓存隔离。无静态兜底冒充已获取，不为目录条目自动注册推理路由。
