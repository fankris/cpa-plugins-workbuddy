# Rebuild23 — 国内 / 国外两渠道，默认 WB 入口

日期：2026-10-07。

## 用户澄清与修复范围
WB / CB 在同一区域内账号互通，区别是入口；默认使用 WB。用户不是要求第三个渠道，也不是要求国内与国外凭据跨区域混用。

- 账号与模型只显示 `cn` / `intl` 两个区域。旧 `global` 是 WB 国际入口的内部兼容标识，不再作为第三个展示渠道。
- 既有账号按区域选择 WB 业务入口；CB 国际域名/region/issuer 的凭据可进入 WB 国际模型目录、积分、推理与令牌刷新路径。
- 删除 CB 国际动态目录 unsupported 和 model.for_auth 强制静态跳过分支。
- 国内继续使用 WB 客户端的现有公共 API：copilot.tencent.com / codebuddy.cn；不猜测替换成 workbuddy.cn。
- 保留官方/原生登录集成，不新增登录页面。现有合法 CB 登录凭据可以用于默认 WB 业务入口；不更改原始登录数据以伪装成 WB 凭据。
- 每区域一个观察来源。国外选择器同时容纳 WB/CB 凭据；观察不改 CPA 路由，不扫描全部账号动态目录。
- 服务入口不再决定存储命名/迁移去重/自动维护政策。新增独立 `credentialOriginService` 仅保存历史存储及维护兼容语义；不参与页面渠道或业务请求选路。防止升级导致现有凭据被重命名、去重、停用策略改变。
- 请求中的旧 sources.global 映射到 sources.intl；明确 intl 优先。前端临时选择状态迁移。旧国际自定义模型配置保留，不重复生成两个品牌的配置变体。
- JWT issuer 域名解析接受 WB/CB 国际后缀，拒绝仅字符串包含 workbuddy.ai 的无关域名。
- 原始 CB domain 保留为凭据元数据；不写 auth，不更换账号身份，不改变CPA选中账号。401仍是失败，不静默请求国内域名。
