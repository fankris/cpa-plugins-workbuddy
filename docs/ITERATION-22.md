# Rebuild 22 — 四个业务工作区完善

日期：2026-10-07。保留 rebuild21 模型中心、五工作区、CPA 原生凭据与配置所有权，以及 /panel 双菜单声明。生产未修改。

## 实现
- Dashboard：连接技术信息折叠；到期列表和可点击待处理列表，未知数据不计为零。
- Accounts：真实 `service` 三渠道字段，兼容 `region`；列表操作收敛到详情，详情按积分/套餐→维护操作→本地诊断层次展示；保留批量签到、导入、分页及上下账号导航。
- Credits：GET `/credits?auth_index=…` 与 GET `/credits` 共用读取实现，最多4个并发任务，保留套餐、试用及签到缓存信息、更新采集时间。读取不调用生命周期协调、保存凭据或修改路由。前端按ID合并，响应不能覆盖 disabled/selected/身份字段，序列保护避免旧响应覆盖新列表。
- Maintenance：POST `/refresh` 原有全账号写备注/生命周期逻辑保留，移到设置“刷新并维护全部账号”，需确认，明确可能停用/恢复账号。不能通过 body 伪装成单账号刷新。
- Tasks：国内账号选择，国际不支持说明；状态计数与可领取优先排序；单项确认包含账号和任务；保留批量接受、旅行、运行记录与取消。拒绝 malformed tasks 响应。
- Settings：自动业务、维护、路由三个分组；错误/加载状态独立；严格区分布尔值、未知运行态和配置差异，不将配置一致宣称为执行成功。
