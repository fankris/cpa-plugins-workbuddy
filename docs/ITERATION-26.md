# rebuild26 — 模型信息分层徽章

按用户选择的“分层徽章”方案实现。仅调整模型信息呈现及来源声明解释，不改变请求路由、模型配置或账号业务。

## 展示结构

1. **名称与来源**：名称附近显示配对徽章，例如 `CN · Dynamic`、`Intl · Custom`。不将渠道与来源拆开做笛卡尔组合，避免暗示 Intl 也有实际未返回的 Dynamic 记录。上游停用的来源单独标注。
2. **能力**：使用带图标、轻色底的 `Vision`、`Tools`、`Reasoning` 徽章，不把未知当支持。不根据模型 ID、家族、名称或图像生成标签推测能力。图像生成不是 Vision 输入能力。
3. **参数**：Context、Max Output、倍率及 Reasoning 档位保留数值区，不全部做成彩色标签。来源参数不一致仍标注其取值来源。

## 多来源语义

- 能力来自当前筛选后保留的来源声明，不是实际调用验证，不代表账号有访问权益。
- 所有当前来源明确支持时显示普通能力徽章；只有部分明确支持时显示虚线徽章及分数，例如 `Vision 1/3`。
- 分母是当前展示来源记录数，包括声明不支持及未确认的记录，不是全球账号数或成功率。
- 点击能力徽章（也可键盘 Enter）打开逐来源详情，分别展示“声明支持 / 声明不支持 / 未声明 / 声明冲突”。切换 CN / Intl、Dynamic / Custom 后重新计算。
- Vision 读取明确 supports_images，存在明确 image_input_conflict 或图像来源布尔值矛盾时不作为支持。
- Tools 读取明确 supports_tool_call。
- Reasoning 读取明确 supports_reasoning、only_reasoning 或已知 Reasoning 档位；显式否定与肯定配置矛盾时标为冲突。off、none、未知档位不作为支持。
- Custom 声明可展示，但始终绑定 Custom 来源，不冒充 Dynamic 证据。
- 无肯定声明时不显示该能力徽章；这不等于证明不支持。详情保留未知与否定的区别。

## 语言与交互

保留 CN、Intl、Dynamic、Custom、Vision、Tools、Reasoning、Context、Max Output 原名，说明文字跟随管理中心语言。产品名、模型 ID、字段名及用户名称不翻译。

徽章采用图标+文字，不仅靠颜色；局部范围同时使用分数和虚线区分。按钮具有模型ID与来源范围的可访问名称、键盘焦点和不少于24px高度。手机参数不重叠，不引入横向滚动；保留紧凑内滚动列表和原生宿主导航。深色模式已检查。
