# rebuild29 — 账号先显示，积分渐进读取

版本：v8.0.15-2.0.0-rebuild.29。CPA 8.0.15 / ABI 1 / schema 6。

## 用户可见变化

- `/accounts` 不再等待上游积分、套餐；直接给身份、CPA 运行态及已有缓存。仍需要本地 SDK 逐账号读取，不是假装零成本。
- 账号页只按需排队可见行；详情优先。不在打开页面时扫描全量账号。
- “读取全部积分”是显式队列，前端并发 2；进度、失败数、停止按钮就地显示。界面不被全局 loading 阻塞，仍可搜索、翻页、查看详情。
- 停止清除等待项、abort 前端请求，旧代际或换登录身份后的结果不能回写新页面。变更账号状态前停止读取；元数据重载重建队列。
- 未知余额显示 `—`。失败保留旧值，但标记“非实时”；停止与未读不算业务失败。显示新鲜覆盖数，汇总只代表已知快照，不声称全量实时余额。
- 新鲜度检查积分自己的 fetched_at，45 秒阈值，每 5 秒重算展示；不循环重试失败项或自动扫描整个账号池。重试由明确读取操作启动。
- 四语言补齐新状态与按钮，CN/Intl 专业标签不变。保留五工作区、原生登录/config、原 /panel、两套菜单 Description、模型分层徽章及上一轮字体布局。

## 后端及兼容性

- 单账号：`GET /credits?auth_index=...`。
- 全目录现在是分页协议：`GET /credits?offset=0&limit=4`；默认/最大 limit=4，按 auth_index 稳定排序。
- 返回 `scope:page`、total、returned、has_more、next_offset、snapshot。后续页必须带 snapshot，身份目录变动或缺失快照返回 snapshot_changed，须从第一页重启。
- 老客户端不可把第一页冒充全量；前端自己的队列使用单账号请求。
- 全局共享 4 个账号槽位；每账号至多积分/套餐两路上游（不是总共只有 4 个 HTTP 请求）。排队获取槽位也受上下文约束。
- 上游整次预算 12 秒，套餐独立至多 3 秒；浏览器读请求 15 秒；队列整体 120 秒。整体到期等同停止，保留尚未读取的状态。
- 套餐失败不抹掉成功积分或已有套餐；缓存发布继续使用字段代际/CAS。失败不续期旧积分。用户取消不当成余额失效证据，实际超时/错误仍记录积分错误。
- 只读不签到、不申领、不写凭据。顺带移除强制刷新里绕过保护的 syncAuthNote：健康或已暂停账号不再从该路径整份写回。
- 继续保留 rebuild28 的不自动启用、未知写入结果保护、同 run_id 只读轮询恢复。

## 明确的取消边界

浏览器停止可保证当前前端不再排队、旧结果不再覆盖页面；不能保证宿主已发出的请求立刻终止。服务端自己的上下文预算仍适用。

CPA 的 host.auth / runtime SDK RPC 缺少上下文取消接口，所以这里不是整个管理调用的绝对墙钟上限。生产宿主 RPC 卡住、代理行为、真实腾讯限流未做实际验收。自动签到/生命周期是另一条独立后台流程，读取停止不等于关闭它们。

- Go race 下身份响应：约 2.6/10.3/48.3/190.3ms（单次本地观测，详见 JSON，非生产 SLA）。
- 慢上游默认预算实测约 12.01 秒；另验证已取消请求零上游、槽位满时等待取消、20 并发调用超时释放槽位、无账号写入。

- 390/1366 慢响应停止，等待迟到结果后仍未合并，不新增请求；工作区无水平溢出。
- 发布二进制通过 C ABI 模拟宿主：实际构建哈希绑定，回调错误/未释放缓冲区为 0。不是实际 CPA 宿主验收。
