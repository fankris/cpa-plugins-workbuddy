## CPAMP 模型／设置页「宿主返回了无法解析的响应」
用户确认错误发生在模型／设置页，未提供具体部署版本或请求抓包。本轮找到并修复一种与之吻合的确定性协议差异：
- seakee/CPA-Manager-Plus 提交 fb3e8f501f47a29b0fa66a5bf31f0f36739750d3 的完整模式路由只代理 /v0/management/*；前端插件配置使用 /plugins/{id}/config。
- 旧插件固定请求 /v8/management/config/plugins/configs/workbuddy。v8 未被代理时返回非 JSON 404（反向代理也可能返回 HTML），此前只能显示解析错误。
- CPA 8.0.15 同时提供 GET/PUT /v0/management/plugins/:id/config 原生别名，不需要修改宿主或建立平行配置存储。

现在先只读确认 v8 配置接口。遇到404/405或成功状态却非有效JSON对象的响应时，尝试同源、保留挂载前缀的 v0 插件配置接口。只有读取成功才选定接口；同一管理身份的并发初始读取合并一次。401/403、网络失败、500不触发这种兼容探测。
选定后，读取、写入和保存后核对固定使用同一接口。写入绝不自动换接口或重发。非法写入回执仍是「结果未确认」；读回失败仍为未确认。只适配插件配置通道，不把所有原生API笼统重写为v0。

证据：tests/fixtures/cpamp-routing-reference.json 锁定3个原始源码文件SHA256，tests/verify-cpamp-contract.py 拉取固定提交核对；浏览器以CPAMP标题栏模拟和v0-only接口夹具复现错误及修复。**不是用户实际CPAMP实例或完整CPAMP服务验收**，也不是把非JSON当作成功。如果部署在升级后仍报错，需要其版本、失败路径及脱敏状态码继续定位。

## 最早到期积分和天数
- 账号余额下方显示最早到期的那批积分及一位小数倒计时，例如「最早到期 1,280 · 12.1天」，不再仅显示7天内合计；12.1天等大于7天的情况也会显示。
- 相同时刻到期的有效积分包合并；晚些到期的积分不混入这个数量。仪表盘及账号详情也补充该倒计时；7天内统计作为独立汇总保留。
- 每30秒更新显示，并在页面重新可见/获得焦点时更新；优先使用新增 server_time_iso 校准和单调计时，不额外请求账单，不在前端改余额。
- 第一批到期后，从当前快照选择下一批未来到期积分。没有可计算日期时显示未知/—，没有未来批次且已有到期包时提示刷新，不显示负天数。不到0.05天显示「<0.1天」，不误写成0天。
- 无时区的积分包日期按UTC+8解析；RFC3339使用给定时区。积分数量仍是账单快照，不宣称本地倒计时证明上游已扣款或余额实时更新。
- PC表格增加「余额 / 最早到期」列说明，移除冗余余额进度条以保留8行可见；手机保留118px账号卡片和明确的最早到期标签。
