# 19：按模型聚合每种渠道的目录与自定义配置

版本 v8.0.15-2.0.0-rebuild.19。生产与云资源未修改；预览使用明确标注的模拟数据。

## 设计解释

用户要的是每种账号渠道当前来源的模型合并视图，而不是全体账号混合，也不是只有一个选中账号的目录。CPA 当前插件仅保存一个全局选中账号，不能虚构三个独立“当前路由账号”。因此国内、WorkBuddy 国际、CodeBuddy 国际各维护一个**查看来源**：匹配全局选中账号时优先沿用，否则从有令牌且未禁用的匹配渠道账号中按 auth_index 选取一个。可手动调整，界面说明选取依据；调整不会写入账号选择、原生配置或推理路由。

“可选来源”仅表示有凭据且未禁用，不代表权益、余额、限流状态或实际推理能力已验证。CodeBuddy 国际目录仍明确 unsupported，不用其凭据试探 WorkBuddy 域名。无账号不等于接口失败。

## 实现

- `/models/hub` 与 `/models/hub/refresh` 是只读聚合；后者强制更新目录缓存，不写路由注册表。原目录/原生配置接口保留。
- 一个渠道只请求一个来源账号，国内/WorkBuddy国际复用企业模型与 v3/config 双来源读取，通道间并发。
- 同一个精确、去首尾空格的 ID 合并一行，不猜测名称、版本后缀或区域后缀等价。
- 动态目录条目全部保留，包括禁用、非聊天、默认或预设条目；不自动注册为可推理模型。
- 显式自定义定义（包括禁用条目）和 pinned 配置独立展示；内置静态兜底不能冒充已获取。models_enabled 成员本身不凭空生成自定义模型。
- 来源类型与账号渠道是两套信息；同一 ID 可同时动态和自定义。渠道徽标区分“目录实际返回”与“配置声明适用”。旧 intl/global 自定义规则的兼容含义覆盖两个国际服务，不等于两个服务实测都支持。
- 上下文、输出、倍率、推理档位不一致显示“按来源不同”；详情保留逐来源参数、账号、接口来源、禁用、工具与图像声明及冲突。未知倍率不当成免费，排序时未知或冲突置后。
- 原“CPA配置 / 账号模型目录”双标签退役。一个列表支持搜索、来源/渠道交集筛选和排序。切换筛选后名称取可见来源，不沿用被隐藏渠道的标签。
- 模型详情内保留原生全局配置开关，仍需确认并读回；不是给目录条目自动注册路由，陈旧读回仍标记待确认。
- 来源选择、筛选和展开状态可随官方宿主语言切换恢复；旧模型页状态键清理。五工作区、仪表盘连接信息、即时业务反馈不变。
