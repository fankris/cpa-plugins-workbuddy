# CPA 主体 / WorkBuddy 扩展边界

当前：rebuild.22。Manager 是业务与交互参考，不是插件架构主体。

| 能力 | 权威归属 | 插件职责 |
|---|---|---|
| 账号存储、身份与文件名 | CPA auth store | 读取、展示与协议解析；不建第二账号池、不改名迁移 |
| 凭据启停、手动刷新 | CPA native v8 | 调用宿主接口；不伪造写回成功 |
| OAuth、通用设置 | CPA / CPAMC | 由宿主原生页面与 ConfigFields 提供；插件不重复配置/登录入口 |
| 模型聚合展示 | 各渠道账号目录 + 显式配置 | 每渠道一个观察来源；动态与自定义分开标注，不写路由或账号选择 |
| 插件模型设置 | CPA 单插件配置对象 | GET/merge/PUT + 修改字段回读核对；不另建配置数据库 |
| 账号是否可路由 | CPA runtime | 同一展示函数；未知不伪装可用，旧错误不覆盖宿主已恢复状态 |
| 调度、限流、HTTP 操作 | CPA | 默认宿主调度；复用 host HTTP operation；保留显式旧兼容模式，不新建通用网关 |
| 日志、用量 | CPA | 上报宿主；原生记录保留。插件无结果历史/导出页，只保留业务页最近动作反馈 |
| WorkBuddy 协议、套餐额度、模型发现 | 插件扩展 | 处理上游特有业务；失败明确降级，缓存不当作真实可用证明 |
| 合法任务与奖励 | WorkBuddy 真实业务状态 | 显示、接受、领取已完成奖励与取消后续批次；不伪造进度 |
| UI 语言主题 | CPAMC | 同源四语言与主题跟随；原 `/panel`，无重复应用标题栏或独立管理壳 |

## 从 Manager 学什么

学习账号状态口径统一、读不到状态时显示未知、保存与运行态生效分开、确认与结果可追踪。**不复制**独立网关、SQLite 账号池、管理密钥系统、Docker 更新、上游分组与另一套调度/统计服务。

## 验证口径

当前验证以 [第十二轮说明](ITERATION-12.md) 和 [摘要](VALIDATION-12.json) 为准。此前真实空宿主测试仅是历史验证，不是当前版本真实业务验收。真实账号推理、刷新写回、业务奖励等仍待隔离账号授权测试。

移动 UI 使用紧凑操作区与自适应卡片分页，不复制 Manager 的独立应用壳；桌面维持 CPA 内置业务页思路。

PC 端增加紧凑汇总筛选、可调分页和双栏详情对照，不新增宿主已有的系统能力。
